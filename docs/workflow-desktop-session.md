# 固定开发客户端的日常服务生命周期 v1

2026-10-31 用户要求：重启电脑后点击易界，自动启动原有服务，不把每次重启都作为需要全量备份的异常恢复。

`contract-impact = semantic`。权威源为 `scripts/workflow-session.py`；消费者为 Desktop 的固定开发入口。用户本次指令授权本地部署流程变化。公共 HTTP/IPC、数据库 schema、镜像、端口、权限、业务审批及旧恢复入口均不变；中央 Contracts PR/pin 为 N/A。原 `workflow-local.py` 的已审核字节和旧打包入口保持不变。

## 正常使用

固定入口调用 `python3 -B scripts/workflow-session.py ensure`。已有服务通过原带凭据 readiness 后复用，并记录原容器、镜像、配置摘要、挂载、编辑器和核验代码摘要。该小型记录不包含凭据或业务数据，不是备份。

原容器已停止时，须与上次就绪记录完全匹配。仅允许普通容器的退出码 0 或 Docker VM 关闭时可能出现的 255；255 保留为原始退出事实，不改写成正常退出。OOM、其他错误、未完成生命周期、异常一次性容器、来源/配置改变均阻断。然后顺序启动原依赖，调用 API/Coze 所属仓的只读存储检查，确认无未完成操作，再启动原应用，核对带凭据 readiness 及启动前后工作流/操作事实（仅允许既有规则规定的正常 principal 审计）。不重放任务，不重建容器，不轮换凭据，不执行 migration，不复制数据。

会话记录 schema v2 将 Docker `HostConfig.Dns/DnsOptions/DnsSearch` 的 `null` 与空数组统一为同一个空设置；非空 DNS、其他字段、镜像及网络身份仍严格参与摘要。实机正常关闭并重开空闲 Docker 后，8 个容器都只有这三项表示差异，按旧表示计算的摘要逐个精确匹配原记录。v1→v2 只接受固定的上一版 controller 来源摘要，并再次验证全部原身份；保留约数 KB 的旧元数据，不能用新摘要覆盖未解释的配置漂移。

客户端和 Host 正常退出后，入口调用 `stop`。使用原 controller 锁及 API→Coze→依赖的 SIGTERM/无限 grace 流程；不关闭用户 Docker，不触及其他项目。清理尚未结束时保留状态，不强杀。电脑关机次序由 macOS/Docker 决定，因此不能承诺任意断电都等价于正常退出；下次仍执行上述身份与存储核验。

如原数据存在非终态操作或真实损坏，不自动备份或“修复”；保留现场并报告，按问题选择处理方式。旧显式恢复入口和保护副本要求仍适用于人工批准的事故恢复。

## 验证边界

单元检查只使用内存中的生命周期状态。实机进行客户端正常退出、原容器正常停止、Docker 无运行容器时从其菜单正常退出、图标自动启动 Docker/原服务及带凭据健康检查；不重启用户电脑，不中断运行中的容器、不强杀、不注入权限或二进制故障。真实 macOS 重启后的全流程尚未现场验证，不能将这些安全检查描述为断电测试通过。
